# 跨平台迁移计划

## 技术决定

- 前台：Flutter / Dart，统一 Windows、macOS、Android。
- 领域核心：继续使用 Rust，不重复实现路由、信任和恢复规则。
- 原生能力：采用 Flutter federated plugin 结构，每个平台单独实现系统音频。
- 高频音频数据：FFI / 原生缓冲区；低频命令和状态：类型化平台网关。

## 迁移阶段

### 0. UI 重置（已完成）

- 新建 `apps/bluebridge/`。
- 统一中文、黑白灰、响应式桌面/移动布局。
- 移除模拟设备、模拟连接、模拟延迟和模拟运行状态。
- 统一 Android、macOS、Windows 品牌资源。
- 增加静态检查和组件测试。

### 1. 平台网关

- 定义设备、输出、权限、路由和错误状态 DTO。
- 使用 Pigeon 或等价代码生成方案保持 Dart / 平台类型一致。
- 为每个平台提供“未接入”实现和契约测试。

### 2. macOS 功能等价

- 将现有 CoreAudio 输出枚举迁入 macOS 插件。
- 将 ScreenCaptureKit 采集和 AVAudioEngine 输出迁入插件。
- 在新 Flutter UI 完成权限、启动、停止、错误与设备刷新流程。
- 功能等价并通过真机验收后，旧 SwiftUI 前台才允许归档。

### 3. Rust FFI

- 为共享核心提供稳定 C ABI。
- 生成 Dart FFI 绑定并明确内存所有权。
- 接入路由校验、环路阻止、链路选择和重连状态。

### 4. Windows 与 Android

- Windows：WASAPI 回环/逐进程采集、标准 A2DP Receiver、多路混音。
- Android：用户授权的播放捕获、AudioTrack、前台服务和后台恢复。
- 每个平台必须使用真实设备状态，禁止开发适配器进入发布构建。

### 5. 跨设备音频与发布

- 局域网发现、双方确认配对和凭据存储。
- 加密实时音频、时钟同步、抖动缓冲和重连。
- 三端签名、安装包、崩溃诊断和更新机制。

## 删除旧工程的条件

旧原生工程当前不删除。对应平台只有同时满足以下条件才可归档：

1. 新 Flutter 应用已覆盖真实音频能力。
2. 权限、错误、恢复和输出设备切换通过实机验证。
3. 发布包可以安装、启动并完成最小音频路由。
4. 没有依赖旧 UI 才能执行的诊断或恢复操作。
