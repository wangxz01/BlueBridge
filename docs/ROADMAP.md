# BlueBridge 开发路线图

项目从一个干净的 Flutter 跨平台基础逐步增加真实能力。每个阶段都必须可编译、可测试，并明确区分已实现和未实现。

## 阶段 0：跨平台基础（已完成）

- 创建 Android、macOS、Windows 共用的 Flutter 应用。
- 完成中文、黑白灰、响应式 UI。
- 建立概览、路由、设备、设置四个入口。
- 移除所有模拟设备、模拟连接、模拟延迟和模拟运行状态。
- 统一三端应用图标。
- 保留 Rust 共享领域核心与测试。

## 阶段 1：平台网关

- 定义音频输出、捕获来源、权限、设备、路由和错误 DTO。
- 建立 Dart 与平台插件之间的类型化接口。
- 区分“未接入、无设备、需要权限、运行中、恢复中、失败”。
- 为网关增加契约测试，禁止演示适配器进入发布构建。

## 阶段 2：macOS 最小音频路由

- 使用 CoreAudio 枚举真实输出设备。
- 使用 ScreenCaptureKit 获取用户授权的系统音频。
- 使用 AVAudioEngine 输出到用户选择的设备。
- 在 Flutter UI 中实现权限、刷新、启动、停止和错误处理。
- 产出第一个可安装、可验证的跨平台架构版本。

## 阶段 3：Rust FFI

- 为共享核心提供稳定 C ABI。
- 生成 Dart FFI 绑定并定义内存所有权。
- 接入路由校验、环路保护、链路选择和恢复状态。
- 为 ABI 和 Dart 映射增加自动化测试。

## 阶段 4：Windows 与 Android 音频

- Windows：WASAPI 回环/逐进程采集、输出选择、标准 A2DP Receiver。
- Android：MediaProjection、AudioPlaybackCapture、AudioTrack、前台服务。
- 在对应操作系统和真实设备上完成最小路由验收。

## 阶段 5：跨设备传输

- 局域网发现和双方确认配对。
- 操作系统凭据库存储。
- 音频编码、加密会话、时钟同步和抖动缓冲。
- 丢包处理、自动重连、多路混音和环路标记。

## 阶段 6：发布

- 三端正式签名、安装包与卸载流程。
- 权限说明、诊断日志、崩溃报告和自动更新。
- 性能、延迟、功耗和长时间运行测试。
